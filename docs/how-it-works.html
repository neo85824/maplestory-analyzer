How MapleStoryAnalyzer works

MapleStoryAnalyzer is a small window that stays on top of the game. Two times each second it reads your level, HP, MP and EXP from the screen. It shows how much EXP you got and how much HP and MP you used.

The program does not read the game memory or the game files. It takes a picture of the screen and reads the text with OCR. OCR makes mistakes, so a large part of the program decides which readings are correct.

The pipeline

Every 500 ms the program does one cycle. One cycle is a tick. A tick has five steps. Each step is in its own file and gives one result to the next step.

The function OverlayApp._do_tick in overlay.py runs the tick. One tick uses approximately 65 ms. OCR uses most of this time.

Each step

1. Where to look regions.py

The stat bar at the bottom of the game has a fixed size in pixels. The level is at the left edge of the window. HP, MP and EXP are at a fixed distance from the right edge. Thus each field has a box that is a fixed number of pixels from an edge.

FieldHorizontal positionVertical position (from the bottom)
LV8 to 92 from the left36 to 6
HP902 to 804 from the right35 to 9
MP738 to 640 from the right35 to 9
EXP572 to 436 from the right35 to 9

The height of 26 pixels is important. A smaller box cuts the top of the digits, and OCR reads 7 as 2. A larger box includes the coloured bar below the text. These values come from one real screenshot at 1366×768.

2. Capture capture.py

GameWindowCapture.grab_fields() does three things:

  1. It finds the game window. It uses the window title and the process name. The title alone is not sufficient, because a browser tab can have the same title.
  2. It makes sure that no window covers the stat bar. The capture takes the pixels that are on the screen. If a chat window is on top of the stat bar, the program would read the chat window. The program tests four points of each field. If one point is in a different window, the tick stops.
  3. It captures the stat bar one time and cuts the four field images from it.

3. OCR ocr.py

OCR reads the text in each field image. The program uses RapidOCR in "recognition only" mode. This mode reads a box that is already known, and it uses approximately 15 ms for each field.

The game font is small (approximately 14 pixels). The program prepares each image before OCR:

  • Greyscale. This removes the green colour of the text and the colour of the bar.
  • 3× larger. Without this, OCR does not see thin characters such as the [ in the EXP field.
  • LV only: black and white. The level is white text on orange. In greyscale, OCR read 51 as 50. Other fields do not use this, because it removes [ and /.

4. Parser parser.py

The parser changes the four text strings into numbers. The result is a StatSnapshot: level, HP and its maximum, MP and its maximum, EXP and its percent. Each value can be empty.

The rule is: if the text does not have the correct form, the value is empty. An empty value is safe, because the window keeps the last good value. A wrong value is not safe, because the program counts it.

OCR textResultReason

5. Before the session overlay.py

_do_tick does three small things before it gives the numbers to the session:

  • It removes HP or MP values that are larger than their maximum. Example: MP [7200/3360] when the real value is 1200.
  • It counts the ticks in which HP, MP and EXP are all empty. After 6 ticks (3 seconds) the status changes.
  • For LV, HP and MP, it replaces an empty value with the last known value. EXP is different: see the next section.

Which readings are correct

In a recording of 29 minutes of real play, approximately one EXP reading in six was wrong. A digit was missing from the value, from the percent, or from both. Or OCR read one digit as a different digit. HP and MP readings are also wrong at times. The program has three methods for this problem.

EXP: the level total exp_total.py

The game shows EXP as a value and a percent. The value divided by the percent gives the total EXP of the level. This is the level total. It does not change until you level up. The game does not show the level total, but all correct readings give the same level total. Wrong readings give different level totals.

LevelTotalEstimator keeps the last 80 different readings. The level total is the value on which most readings agree. After that, the program compares each new reading with the level total. If the reading does not agree, the program ignores it.

RuleThe problem that it prevents
Only different readings count. The same text 100 times counts as one.A character that does not move repeats the same wrong reading. In one recording, S255[1 12%] was in 379 of 429 ticks.
A minimum of 3 readings must agree. They must cover a range of 0.05 percent.OCR reads "11.83" as "1.83" many times. For a short time, these wrong readings agree with each other.
A reading that is lower than the last good reading must occur in 3 different readings or 10 ticks.8721[111%] for 87210 [11.04%]. A digit is missing from the two numbers, so the ratio is correct. But EXP cannot decrease in a level.
The program ignores a reading without a percent. Exception: the percent is missing for 10 ticks.930458(7162]: the value and the percent became one number. One session ended at +823,919 because of this.
If the level increases and EXP decreases, the program starts a new level total.A real level-up. The two signals are necessary, so that one wrong level reading does not reset the level total.
If 8 different readings in sequence do not agree, and 5 or more agree on a new total, the program uses the new total.A level-up that the level field did not show, or a level total that was wrong from the start.

Before the level total is known, the program uses a simpler test: it ignores a reading if its level total is more than 25% different from the last tick.

EXP diff: one measurement for each level rate.py

In one level, the EXP diff is the current EXP minus the start EXP. This uses only the last good reading. Thus one wrong reading is wrong for one tick only, and the next tick corrects it.

The program does not add each small increase. An older version did, and one bad frame added 101 million EXP permanently.

At a level-up, the program closes the old level and opens a new one. The old level adds its level total minus its start EXP. The new level starts from zero. The percent is the sum for each level: 40% of one level and 5% of the next level shows 45%.

HP loss and MP loss: a sum, with two tests loss.py

Loss cannot be "end minus start". If you lose 5,000 HP and use potions, the start and the end are the same. Thus the program adds each decrease, tick by tick. A wrong reading in a sum stays permanently, so LossTracker tests each reading two times:

  • The maximum must stay the same. Max HP and max MP change only at a level-up. A different maximum shows a wrong reading. Example: 1663/2816 read as 16632/816. The program accepts a new maximum after 2 ticks if the level also increased, or after 3 ticks if not. It never accepts a maximum that is more than 2 times or less than half of the old one.
  • A large change must occur two times. If the value changes by more than half of the maximum in one tick, the program waits. If the next reading is near, the change is real and the program counts it one tick later. If the next reading is normal, the program ignores the change.

Before these tests, a character that did not move "lost" 142,258 MP in one session. All of it came from wrong readings.

Calibration: do not use the first frame rate.py

When a session starts, the program first confirms three values: max HP, max MP and start EXP. Each value must be the same in 3 ticks, or in 2 ticks if something on the stat bar changed. During this time the status shows "Calibrating" and the program counts nothing.

A character that does not move can repeat one wrong reading, and calibration can accept it. Thus, when the level total is known, the program tests the start EXP again. If the start EXP is wrong, the program replaces it with the first reading that agrees with the level total.

Sessions

A session is one period of play with a fixed start. "EXP diff" always means: since this session started. The program has three states.

  • Timer. The session length is in Settings (default: 10 minutes). The timer uses real time. It continues when the program cannot read the game.
  • Pause and Resume. At Resume, the program takes new start points for HP, MP and EXP from the screen. For EXP, it waits for the first good reading.
  • Saved session. A saved session is a SessionSummary: start time, end time, start EXP, end EXP, EXP diff, percent, HP loss, MP loss, level total and session length.

Tests and debug

.venv/bin/python -m pytest tests/ -q        # 181 tests, approximately 4 seconds

The tests run on Linux without the game. There are three types:

  • Real OCR on the real screenshot (test_ocr_pipeline.py). This test shows that the field boxes are in the correct position.
  • Replay of recorded sessions (test_exp_total.py, test_captured_regression.py, test_levelup.py). The tests send the text from real play through the tick loop again. Each problem on this page has a test of this type.
  • Window logic without a window (test_run_state.py). The real OverlayApp functions run with simple replacement widgets.

If a value looks wrong during play, start the program from source:

.venv\Scripts\python scripts\run_overlay.py > run.log
.venv\Scripts\python scripts\run_overlay.py --save-crops crops

The first command writes each tick to a log: the OCR text, the parsed values, and a line for each EXP reading that the program ignored. The exe does not write a log. The second command saves the image of each reading that the program ignored, with an index file. These images are necessary to make the OCR better.

Limits

  • Windows only. Only 1366×768 is tested. The game must be the active window.
  • OCR is still wrong for approximately one EXP reading in six. The program ignores these readings. Thus the EXP row can stay the same for some seconds. In the recording, the longest time was approximately 50 seconds, when the character did not move.
  • MP loss can be too small. OCR at times reads a first digit 1 as 7 (7200 for 1200). The program ignores these ticks, so it does not see MP that you use during them.
  • A level-up during a pause is not counted.
  • The program saves nothing to disk. History and settings are lost when you close the window.
  • At very high levels, the level total takes more time. EXP must change by 0.05% of the level first. Before that, the simpler test is active.
  • v1.0.6 is not tested in the live game. The tests used recorded readings from real play.
